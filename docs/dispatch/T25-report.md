子代理在验证过程中用探针实测了两个**真实缺陷**（数据为其探针记录，主线复跑全量套件验证通过）：

1. **失败路径幻觉**：工具调用失败时旧实现沿用"能答则答"续链指令，本地 7B 拿到失败信息后**约半数凭猜测编造数据**（跨源 JOIN 失败场景：0/4 修正重试）→ 新增失败专属指令 `TRAILER_RETRY`（"本轮没有数据、修正重试、禁止编造"）后 4/4 修正重试、5/5 无幻觉。**这是防幻觉的关键防线**（工具类 NL2SQL 的编造数据是致命缺陷）。
2. **tools 数组模板冲突**：Ollama 的 qwen 模板见请求携带 `tools` 会注入自带 `<tool_call>` 脚手架，与文本化协议冲突——模型在本应发起调用的回合（典型：带历史的第二轮）约半数退化成寒暄文本（同构造探针：带 tools 9/20 vs 去掉 11/11）。改为**请求不携带 tools 数组**（白名单注册保留），工具认知由 sysPrompt 清单承担。
