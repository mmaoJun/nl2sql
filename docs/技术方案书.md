# NL2SQL 智能查询系统 - 技术方案书

> 活文档说明：本文随实现持续更新（最近同步 2026-10-12，反映 W2/W3 完成状态）；细节以仓库实现与 `docs/dispatch/` 各任务报告为准。

## 1. 项目目标

基于 ≤7B 大模型，构建支持多数据源的自然语言查询系统。用户通过自然语言提问，系统自动生成 SQL 并返回结果（仅 SELECT）。

**核心能力**：
- 元数据自动分析
- 自然语言 → SQL（含复杂查询、统计、关联）
- 多数据源适配（MySQL、PostgreSQL、Hive、API）
- 安全控制（只读、防注入、审计）

## 2. 模型选型

### 2.1 候选模型对比

| 模型 | 参数量 | SQL/代码能力 | Tool Calling | 中文 | 本地部署 |
|---|---|---|---|---|---|
| **qwen2.5-coder:7b** | 7B | 强（代码特化，HumanEval 领先） | Ollama 支持，7B 下不稳定 | 优秀 | 4-5GB 显存 |
| qwen2.5:7b | 7B | 中上（通用，非代码特化） | 同 Ollama | 优秀 | 4-5GB |
| deepseek-coder-v2:6.7b | 6.7B | 强（代码特化） | Ollama 支持 | 良好 | ~4GB |
| glm-4:9b | 9B | 中上 | 支持 | 优秀 | ~6GB |
| llama3.1:8b | 8B | 中 | 支持 | 一般 | ~5GB |

### 2.2 选型结论

**本地模型：qwen2.5-coder:7b（Ollama）**
- 7B 参数量，符合课题硬约束
- coder 系列 SQL 生成能力最强（HumanEval / MBPP benchmark 领先）
- 通义千问系列中文理解优秀，自然语言→SQL 语义准确

**云端对比：qwen 系列**
- qwen-plus / qwen-max — Tool Calling 原生稳定，作为 Agent 模式基准
- 同一批测试用例，量化本地 7B 与云端大模型的差距
- 重点对比：复杂查询准确率、Tool Calling 稳定性、延迟

### 2.3 参数量对 LLM 能力的影响

| 能力维度 | 7B 模型表现 | 大模型（>13B）表现 | 对 NL2SQL 的影响 |
|---|---|---|---|
| 单表简单查询 | 准确率高（>90%） | 准确率高 | 7B 可满足基础场景 |
| 多表 JOIN | 准确率下降（~60%） | 准确率高（>90%） | 7B 需要 Agent 辅助探索表关系 |
| 复杂子查询 | 容易出错（嵌套逻辑混乱） | 稳定 | 7B 需要 validate_sql 工具自纠 |
| Tool Calling | 参数解析偶有错误 | 稳定可靠 | 7B 多轮工具调用成功率低于大模型 |
| 中文语义理解 | 良好 | 优秀 | 模糊表述（"大概""差不多"）7B 理解弱 |
| 推理步数 | 3-5 步可完成 | 10+ 步仍稳定 | 7B 需限制 maxIterations，避免发散 |

**结论**：7B 模型在简单查询场景可用，但复杂查询需要 Agent 模式补偿（按需获取 Schema + 自我纠错）。云端大模型作为基准，用于量化 7B 的能力边界。

### 2.4 排除理由

| 模型 | 排除原因 |
|---|---|
| qwen2.5:7b | 通用版 SQL 能力弱于 coder 版，同参数量下无优势 |
| deepseek-coder-v2:6.7b | 中文理解弱于 Qwen，自然语言→SQL 依赖中文语义理解 |
| glm-4:9b / llama3.1:8b | 参数量 >7B，不符合课题硬约束 |

### 4.2 Agent 模式流程

```
用户问题 → ReActAgent.call()
            ├─ LLM 思考 → 调用 list_tables() → 了解表
            ├─ LLM 思考 → 调用 get_schema("orders") → 查结构
            ├─ LLM 思考 → 调用 sample_data("orders", 3) → 看样例
            ├─ LLM 思考 → 生成 SQL
            ├─ LLM 思考 → 调用 validate_sql(sql) → 校验
            ├─ 校验失败 → LLM 根据错误修正 → 再次校验
            └─ LLM 输出最终回答 → 提取 SQL → 执行返回结果
```

**优势**：
- 按需查询 Schema，不全量塞 prompt
- 主动探索数据（看样例理解字段含义）
- 自我纠错（校验失败后自动修正）
- 流式事件推送（用户实时看到 Agent 思考过程）

### 5.2 Agent 工具定义

```java
public class NL2SQLTools {

    private final MetadataService metadataService;
    private final DataSourceFactory dataSourceFactory;
    private final SqlSecurityChecker sqlSecurityChecker;

    @Tool(name = "list_tables", description = "列出指定数据源中所有表名及注释")
    public List<TableInfo> listTables(
        @ToolParam(name = "datasource_id", description = "数据源ID") Long datasourceId
    ) {
        return metadataService.listTables(datasourceId);
    }

    @Tool(name = "get_schema", description = "获取指定表的列定义（列名、类型、注释、主键）")
    public List<ColumnInfo> getSchema(
        @ToolParam(name = "datasource_id") Long datasourceId,
        @ToolParam(name = "table_name", description = "表名") String tableName
    ) {
        return metadataService.getColumns(datasourceId, tableName);
    }

    @Tool(name = "sample_data", description = "获取指定表的前 N 行数据样例")
    public SampleResult sampleData(
        @ToolParam(name = "datasource_id") Long datasourceId,
        @ToolParam(name = "table_name") String tableName,
        @ToolParam(name = "limit", description = "行数，默认3") Integer limit
    ) {
        return dataSourceFactory.getAdapter(datasourceId).sample(tableName, limit);
    }

    @Tool(name = "validate_sql", description = "校验 SQL 语法和安全性，返回是否合法及错误信息")
    public ValidateResult validateSql(
        @ToolParam(name = "datasource_id") Long datasourceId,
        @ToolParam(name = "sql", description = "待校验的 SQL") String sql
    ) {
        return sqlSecurityChecker.validate(datasourceId, sql);
    }

    @Tool(name = "execute_sql", description = "执行只读 SQL 查询，返回结果集")
    public QueryResult executeSql(
        @ToolParam(name = "datasource_id") Long datasourceId,
        @ToolParam(name = "sql", description = "待执行的 SELECT SQL") String sql
    ) {
        return dataSourceFactory.getAdapter(datasourceId).executeQuery(sql);
    }
}
```

### 5.3 Agent 初始化与调用

```java
@Configuration
public class AgentConfig {

    @Bean
    public DashScopeChatModel chatModel() {
        return DashScopeChatModel.builder()
            .apiKey(System.getenv("DASHSCOPE_API_KEY"))
            .modelName("qwen-plus")
            .build();
    }

    @Bean
    public Toolkit nl2sqlToolkit(MetadataService metadataService,
                                  DataSourceFactory dataSourceFactory,
                                  SqlSecurityChecker sqlSecurityChecker) {
        Toolkit toolkit = new Toolkit();
        toolkit.registerTool(new NL2SQLTools(metadataService, dataSourceFactory, sqlSecurityChecker));
        return toolkit;
    }

    @Bean
    public ReActAgent nl2sqlAgent(DashScopeChatModel chatModel, Toolkit toolkit) {
        return ReActAgent.builder()
            .name("NL2SQLAgent")
            .sysPrompt(loadSystemPrompt())
            .model(chatModel)
            .toolkit(toolkit)
            .maxIters(5)
            .build();
    }
}
```

### 5.4 流式事件推送

```java
// Controller
@GetMapping(value = "/api/v1/chat/stream", produces = MediaType.TEXT_EVENT_STREAM_VALUE)
public Flux<ServerSentEvent<AgentEvent>> chatStream(ChatRequest request) {
    Msg userMsg = Msg.builder()
        .role(MsgRole.USER)
        .content(TextBlock.builder().text(request.getQuestion()).build())
        .build();

    return nl2sqlAgent.call(userMsg)
        .toFlux()
        .map(event -> ServerSentEvent.builder(toAgentEvent(event)).build());
}

// 实际契约（2026-10-12 落地，见 docs/dispatch/T9-report.md §2）：
// SSE 事件名 TEXT_DELTA / TOOL_CALL / TOOL_RESULT / FINAL / ERROR
// TOOL_CALL 携带 {tool, callId, input}；TOOL_RESULT 携带 {tool, callId, summary, success}
// FINAL 携带与同步接口一致的 ChatResult（含 sessionId）
// 本地通道 stream=false：TEXT_DELTA 允许缺失（整段一条或没有），FINAL 必定送达
```

### 5.5 SQL 安全校验（纵深防御）

| 层 | 机制 |
|---|---|
| L1 | 关键词黑名单（DROP/DELETE/INSERT 等） |
| L2 | JSqlParser AST（验证 SELECT） |
| L3 | 注入检测（堆叠查询、UNION 注入） |
| L4 | 数据库只读用户（最终防线） |

校验逻辑封装在 `validate_sql` 工具内，Agent 生成 SQL 后会主动调用校验；
`execute_sql` 内部同样强制"先校验再执行"（纵深防御，不依赖模型自觉）。

**实现补充（2026-10-12）**：HTTP 层已落地 JWT 认证（除 `/api/v1/auth/**`、`/api/v1/health`、docs 外全部需认证，未认证返回 403）与操作审计日志（每次问答落 `audit_logs`：提问、生成 SQL、结果行数与成败）。

## 7. 高级能力支持

### 7.1 复杂查询（JOIN、子查询）

**Agent 优势**：先查多个表结构 → 理解关联关系 → 看样例数据确认外键 → 生成后 validate 自纠

### 7.2 统计分析（聚合、分组、排序）

**Prompt 增强**：系统提示强调聚合函数用法（COUNT/SUM/AVG/GROUP BY）+ Few-Shot 示例

### 7.3 关联查询（外键、多表、树形）

**Agent 探索**：get_schema 发现外键列 → sample_data 验证关系 → WITH RECURSIVE 支持树形

### 7.4 模糊匹配

**Prompt 规则**：用户说"包含" → LIKE；"以...开头" → LIKE 'xxx%'

### 7.5 数据洞察（TOP N、占比、趋势）

**Agent 优势**：先 sample_data 看数据分布，再决定分析策略

## 10. 风险与应对

| 风险 | 应对 |
|---|---|
| Ollama 无官方 AgentScope 扩展 | 已落地：OpenAI 兼容通道 + `TextualToolCallFormatter`（文本化工具调用还原 + 出站协议统一），实测稳定 |

| Agent 延迟超标 | maxIterations=5 + streamEvents 流式展示 + 工具结果缓存 |
| 准确率提升不足 | 优化系统提示 + 丰富 Few-Shot + 如实记录分析 |
